# Доменная модель

Все сущности живут внутри арендатора: у каждой записи есть `tenantId`.
Определения — `src/lib/types.ts`.

## Связи

```
Tenant ──┬── Branch
         ├── Department ─── User ─── WorkSession
         ├── Channel ─── Lead ──┐
         │                      ▼  конвертация
         ├── Student (контакт) ─┴── Deal ─── University ─── Program
         │      │                    │  │
         │      └── StudentDocument ─┘  └── Deadline (вычисляется)
         ├── Pipeline ─── Stage
         ├── Project ─── Task
         └── TimelineEvent  (история лида, сделки, контакта, сотрудника)
```

## Tenant

Агентство. Ключевое поле — `slug`: он же поддомен. Плюс собственный домен,
тариф, число мест, филиалы, язык интерфейса по умолчанию, курс доллара
(`usdRate`) для пересчёта стоимости обучения и `edition` — версия продукта,
от которой зависит набор доступных модулей.

## User

Сотрудник агентства. Роль (`Role`) задаёт и права, и зону видимости —
см. [ROLES.md](ROLES.md). Привязан к филиалу и к подразделению
(`Department`). В карточке — день рождения, два номера телефона (рабочий
и личный) и дата приёма на работу.

## Department

Подразделение компании: имя, родитель и руководитель. Дерево подразделений
рисует раздел «Сотрудники → Структура компании».

## WorkSession

Отметка рабочего дня: начало, конец, суммарный перерыв и признак «сейчас на
перерыве». Отчётность по часам считается только отсюда — ручного ввода часов
нет, иначе отчёт врёт.

## Lead

Необработанное обращение: имя, телефон, почта, источник, канал и комментарий.
Проходит стадии `new → qualification → in_progress` и заканчивается
`converted` либо `junk`.

**Правило уникальности.** Один человек — один контакт и один активный лид,
потому что номер телефона у человека один. `findDuplicate()` сверяет телефон
(по цифрам, без учёта формата), email и номер паспорта; при совпадении новая
карточка не создаётся, а обращение попадает в историю существующей.

Конвертация (`convertLead`) создаёт контакт и первую сделку, закрывает лид
и связывает их: `Lead.convertedContactId` и `Lead.convertedDealId`,
`Student.leadId`, `Deal.leadId`. Если контакт с таким телефоном уже был,
создаётся только сделка.

## Channel

Канал продаж: Instagram Direct, Telegram-бот, почта агентства, телефония.
Хранит статус подключения и поток лидов в месяц. Сами интеграции — следующий
этап; модель и интерфейс подключения уже есть.

## Pipeline / Stage

Воронка: у лидов и у сделок они разные, у агентства их может быть несколько
(поступление в вуз, языковые курсы). Стадия хранит подпись на двух языках,
цвет (палитра или произвольный HEX) и подсказку. **Стадии — это данные,
а не константы в коде**: агентство переименовывает и перекрашивает их
в «CRM → Воронки», и доска, карточка и дашборд сразу это показывают.

## Student

Профиль студента. Отдельно вынесен `StudentProfile` — то, по чему идёт подбор:

| Поле | Зачем |
|---|---|
| `topik` (0–6), `topikExpiresAt` | главный фильтр по корейским программам, сертификат имеет срок |
| `ielts`, `gpa` | англоязычные треки и требования вузов |
| `budgetPerYear` | решающий фактор почти в каждой семье; в долларах, как публикуют вузы |
| `preferredCities` | Сеул / Пусан / регионы — влияет и на стоимость жизни |
| `preferredMajors` | медицина, инженерия, IT, дизайн… |
| `preferredOwnership` | национальный / государственный / частный |
| `degreeLevel`, `intake` | языковые курсы, бакалавриат, магистратура; набор |
| `needsDorm`, `needsScholarship` | влияют на полную стоимость года |

## Deal

Сделка = связка «контакт × программа вуза × набор», то, что раньше называлось
заявкой. Идёт по стадиям своей воронки: `new → consultation → matching →
documents → submitted → university_review → offer → visa → departed`
(и `lost` в любой момент).

Хранит воронку, куратора, приоритет, ближайший внешний дедлайн, сумму договора
и оплату (**в сумах** — см. [MONEY-AND-LANGUAGE.md](MONEY-AND-LANGUAGE.md)).
У одного контакта сделок может быть сколько угодно — параллельные подачи
в разные вузы это норма. Лидов у того же человека несколько быть не может.

## TimelineEvent

История карточки: смена стадии, комментарий, дело со сроком, входящее
сообщение из канала, платёж, действие с документом, системная запись.
Привязана к лиду, сделке, контакту или сотруднику. Сюда же уходит повторное
обращение человека, который уже есть в базе, — вместо второй карточки.

## Project

Проект объединяет задачи в общую цель (набор 2027 Весна, сверка каталога,
открытие филиала): участники, руководитель, срок и статус.

## StudentDocument

Пункт чек-листа досье: тип, файл, версия, статус
(`missing → requested → uploaded → verified | rejected | expiring`),
срок годности и признак «нужен апостиль». Базовый чек-лист — `DOCUMENT_CHECKLIST`
в `labels.ts`; часть пунктов появляется по профилю (нет TOPIK — нет и строки).

## Task

Задача от руководителя сотруднику: исполнитель, автор, срок, приоритет, статус
и привязка к контакту, сделке или проекту.

## Deadline

Не хранится, а **вычисляется** (`scopedDeadlines`) из трёх источников:
дедлайны сделок, сроки годности документов, сроки задач. Один источник правды:
поменялась сделка — сам собой поменялся календарь.

## University / Program

Вуз: город, регион, форма собственности, рейтинг, визовый статус, общежитие,
взнос, максимальный грант, требования (TOPIK/IELTS/GPA/счёт в банке/срок после
выпуска), наборы и список программ. Программа: направление, уровень, язык,
стоимость года, требования по языку.

Поле `dataStatus` (`draft` | `verified`) и `sourceUrl` — служебные: они
показывают, сверена ли карточка с официальным источником. Сейчас все записи —
черновики с демо-цифрами, и интерфейс об этом честно предупреждает.
