# Архитектура

## Принцип

Три слоя, между ними — только типы:

```
данные (src/lib/data)  →  домен (src/lib/*.ts)  →  интерфейс (src/app, src/components)
```

UI никогда не ходит в данные напрямую: он получает их из `queries.ts`, а тот
уже применяет арендатора и зону видимости роли. Когда моки заменятся базой,
изменится только `src/lib/data` — страницы останутся прежними.

## Структура

```
src/
  middleware.ts            определение арендатора по Host до рендера
  app/
    layout.tsx             оболочка: рельса навигации + шапка
    actions.ts             серверные действия (переключение арендатора/сотрудника)
    page.tsx               дашборд
    students/              база студентов + карточка
    applications/          канбан-воронка + карточка заявки
    documents/             досье документов
    tasks/                 доска задач
    deadlines/             календарь сроков
    universities/          каталог вузов + карточка вуза
    finance/               договоры и оплаты
    team/                  сотрудники и матрица прав
    settings/              домен, брендинг, роли, филиалы, тариф
  components/              оболочка, примитивы, клиентские модули с фильтрами
  lib/
    types.ts               доменная модель
    rbac.ts                роли, права, зоны видимости
    tenants.ts             арендаторы, разбор Host, валидация поддомена
    session.ts             сессия = арендатор + сотрудник
    queries.ts             доступ к данным с учётом зоны видимости
    matching.ts            подбор вуза под портфолио студента
    i18n.ts                тип Loc {ru, uz} и translator(locale)
    strings.ts             строки интерфейса
    labels.ts              статусы, этапы, справочники — тоже двуязычные
    format.ts              formatters(locale): даты, деньги, склонения
    data/                  демо-данные
```

## Поток запроса

1. `middleware.ts` читает `Host`, определяет арендатора и кладёт его в заголовок
   `x-orbis-tenant`.
2. `getSession()` в layout собирает сессию: арендатор + текущий сотрудник + его
   роль и зона видимости.
3. Страница вызывает `scoped*()` из `queries.ts` — данные приходят уже
   отфильтрованными по арендатору и роли; `translator(session.locale)` и
   `formatters(session.locale)` дают язык и форматы.
4. Права на действия проверяются через `can(role, module, action)`: кнопки
   «Добавить», «Экспорт», «Перевести этап» появляются только у тех, кому можно.

## Серверное и клиентское

Серверные компоненты по умолчанию. Клиентские — ровно четыре места, где нужна
интерактивность без перезагрузки: таблица студентов, доска заявок, доска задач,
каталог вузов, плюс шапка и досье документов. Логика подбора (`matching.ts`) —
чистые функции без зависимостей, поэтому одинаково работают и на сервере
(карточка студента), и в браузере (живые фильтры каталога).

## Что будет при переходе на базу

- `src/lib/data/*` → репозитории поверх Postgres (Prisma/Drizzle).
- `tenantId` остаётся обязательной колонкой во всех таблицах; политика
  изоляции — на уровне запроса и RLS.
- `queries.ts` становится сервисным слоем: те же сигнатуры, внутри SQL.
- Серверные действия из `actions.ts` вырастают в мутации с аудитом
  (кто, что и когда изменил — лента событий уже есть в модели).
