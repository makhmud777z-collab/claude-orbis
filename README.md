# Orbis System

CRM для консалтинговых агентств, которые отправляют студентов на учёбу в Корею.

Один арендатор — одно агентство со своим поддоменом: `agencyx.orbisystem.us`.
Внутри: CRM с лидами, сделками и контактами, досье документов, задачи и
проекты, календарь с делами по часам, сотрудники с живой структурой компании
и учётом рабочего дня, администрирование прав и каталог корейских вузов
с подбором под портфолио конкретного студента.

Продукт развивается тремя версиями, и версия — это реальный набор модулей у
агентства (`Tenant.edition`), а не строчка в прайсе:

| Версия | Что входит | Состояние |
|---|---|---|
| **01 / MVP** — University Finder | каталог вузов, профиль студента, подбор, шорт-лист и сравнение | функциональность закрыта, ждёт реальных данных |
| **02 / CRM** | лиды, сделки, контакты, воронки и каналы продаж, документы, задачи и проекты, календарь, сотрудники, администрирование | собрано на демо-данных |
| **03 / Advanced** | кабинет студента, автоматизация, AI-подбор | не начато |

Навигация = права роли ∩ модули версии. MVP-агентство открывает систему сразу
каталогом вузов — дашборда и сделок у него нет. Подробнее:
[docs/ROADMAP.md](docs/ROADMAP.md).

## Запуск

```bash
npm install
npm run dev      # http://localhost:3000
```

Проверки: `npm run typecheck`, `npm run build`, `npm run qa`
(браузерный прогон: маршруты, роли, сценарии, адаптив — см.
[scripts/qa](scripts/qa/README.md)).

Для показа есть кликабельный прототип одним HTML-файлом — открывается без
сервера и собирается из тех же данных, что и продукт:
[scripts/prototype](scripts/prototype/README.md).

### Проверить мультиарендность локально

Поддомены работают и на `localhost`:

```
http://seoulway.localhost:3000     → Seoul Way Education (Ташкент, 2 филиала)
http://agencyx.localhost:3000      → Agency X (Алматы)
http://hanbridge.localhost:3000    → Hanbridge Consulting (Бишкек)
```

Без поддомена арендатор берётся из cookie — переключатель в меню пользователя
справа сверху. Там же переключение сотрудника: интерфейс, объём данных и набор
разделов меняются по роли.

## Разделы

Меню повторяет структуру портала Битрикс24: крупные разделы раскрываются
в список страниц.

| Раздел | Страницы | Что делает |
|---|---|---|
| Дашборд | — | Сводка дня: воронка, дедлайны недели, задачи, лента агентства |
| CRM | Лиды · Сделки · Контакты | Обращение → контакт → сделки. Канбан с перетаскиванием или список — на выбор, история в каждой карточке. Воронка переключается в шапке «Лидов» и «Сделок» |
| Задачи и проекты | Задачи · Проекты · Отчёты | Доска задач, проекты с прогрессом, загрузка сотрудников |
| Документы | — | Папка-досье на каждого контакта, статусы, апостиль, сроки годности. Документ запрашивается у студента и проходит путь «запрошен → получен → проверен» (или возвращается на доработку) |
| Дедлайны | — | Автоматически собираются из сделок, документов и задач |
| Календарь | — | Месяц, неделя и день. В дневном срезе — часы с красной линией текущего времени, встречи сотрудника и сроки из других разделов |
| Каталог вузов | Каталог · Шорт-лист | Вузы, программы, дедлайны подачи, подбор под портфолио и сравнение по 16 критериям |
| Финансы | — | Договоры, оплаты, дебиторка, срез по менеджерам |
| Сотрудники | Сотрудники · Структура компании · Отчётность | Карточки с личными данными и нагрузкой (админ их редактирует), живое дерево подразделений с переносом людей, часы из отметок рабочего дня |
| Администрирование | закрыто кодом | Все настройки портала в одном месте: воронки, каналы продаж, карточка просмотра, пользователи, права, домен, брендинг, филиалы, тариф, курс доллара |

Отдельного раздела «Студенты» нет: человек заводится один раз как **контакт**,
а его подачи в вузы живут отдельными **сделками** — по одной на вуз.

## Портал сотрудника и портал владельца

Это два разных места, и граница между ними — код.

Менеджер и оператор работают: лиды, сделки, контакты, задачи, документы,
календарь. **Ни одной настройки они не видят** — ни шестерёнки над доской,
ни пункта меню, ни переключателя агентства в шапке. Сломать воронку
случайным кликом попросту нечем.

Всё, что настраивает портал, живёт в разделе «Администрирование» за кодом
входа: воронки и стадии, каналы продаж, поля карточки на канбане,
пользователи и права, домен, брендинг, филиалы и тариф. Код задаётся там же
(«Настройки портала → Код входа»), по умолчанию `7777`, и хранится у того,
кто портал ведёт. Замок закрывается вместе с браузером.

## Правила CRM

- **Один человек — одна карточка.** Ключ человека — номер телефона. Повторное
  обращение не создаёт второго лида: система находит дубль (телефон, email,
  паспорт) и пишет обращение в историю существующей карточки.
- **Лидов у человека не бывает несколько, сделок — сколько угодно.** Лид живёт
  до квалификации; после конвертации появляются контакт и первая сделка.
- **Стадии — это данные, а не константы.** Название и цвет каждой стадии
  агентство меняет в настройках CRM, палитрой или HEX-кодом.
- **Рабочий день отмечается из меню профиля**, и отчётность по часам считается
  только из этих отметок — ручного ввода нет. Счётчик идёт вживую с секунды
  нажатия и останавливается на перерыв.
- **Права роли редактируются** в «Администрировании»: изменение сразу меняет
  и меню сотрудника, и объём данных, который он видит.
- **Зависшие сделки видны.** Карточка, которая неделю стоит на одной стадии,
  помечается прямо в списке: главный вопрос к доске — не «где карточки»,
  а «где они встали».

## Интерфейс

**Меню настраивается под себя.** Разделы раскрываются независимо друг от
друга — открытый CRM не закрывается от того, что вы открыли «Задачи».
Рельсу можно свернуть до иконок, а нужную страницу закрепить в корне меню,
чтобы не раскрывать раздел по десять раз в день. Выбор запоминается.

**Фильтр один на все разделы.** Умный фильтр Битрикса: слева готовые пресеты
и сохранённые сотрудником наборы, справа — поля, которые добавляются и
убираются кнопкой «Добавить поле». Условия применяются по «Найти», живут в
адресе страницы (`?q=…&f_stage=…`) — значит, отфильтрованный список можно
отправить коллеге ссылкой.

**Две темы.** Светлая по умолчанию, как в Битриксе; тёмная переключается
внутри кнопки профиля, там же, где начинается рабочий день. Выбор хранится
в cookie и читается на сервере, поэтому при перезагрузке нет вспышки чужой
темы. Тёмная — не инверсия светлой: глубина набирается подъёмом поверхностей,
а не тенями.

Ни одного нативного виджета браузера: выпадающие списки, календарь, флажки,
модальные окна и подсказки — свои, чтобы портал выглядел одинаково во всех
браузерах и в обеих темах.

## Язык и деньги

Интерфейс двуязычный: русский и узбекский, переключение в шапке. Забытый
перевод — ошибка компиляции, а не пустое место на экране.

Договоры агентства ведутся **в сумах**. Стоимость обучения в корейских вузах
остаётся в долларах (так её публикуют сами вузы), рядом система показывает
пересчёт по курсу агентства: `$7 800 · 101 млн сум`. Подробности —
[docs/MONEY-AND-LANGUAGE.md](docs/MONEY-AND-LANGUAGE.md).

## Стек

Next.js (App Router) · React 19 · TypeScript · Tailwind CSS 4.
Данные — типизированные моки в `src/lib/data`, за теми же интерфейсами позже
встаёт база. Серверные компоненты по умолчанию, клиентские — только там, где
нужны фильтры и переключатели.
