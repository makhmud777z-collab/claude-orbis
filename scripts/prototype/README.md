# Кликабельный прототип

Один HTML-файл без сборщика и сервера: открывается двойным кликом и
показывает портал целиком — меню, канбан с перетаскиванием, карточки
с историей, настройки воронки, права доступа, каталог вузов.

Нужен для показа: клиенту не нужно ставить Node, а ссылка открывается
с телефона. Данные берутся не из отдельного мока, а **из тех же сидов,
что и продукт** — иначе прототип разошёлся бы с системой за неделю.

```bash
npx tsx scripts/prototype/data.ts   # выгрузить данные из src/lib/data
node scripts/prototype/build.mjs    # собрать build/prototype.html
node scripts/prototype/check.mjs    # прогнать браузером (нужен playwright)
```

## Что внутри

| Файл | Что делает |
|---|---|
| `data.ts` | выгружает сиды и справочники в `build/data.json` |
| `head.html` / `body.html` | оболочка: палитра, типографика, каркас страницы |
| `src/01-core.js` | язык, даты, деньги, версии продукта, права, меню, иконки |
| `src/02-matching.js` | подбор вуза — перенесён из `src/lib/matching.ts` без изменений |
| `src/03-state.js` | состояние, зоны видимости, воронки, дедупликация, рабочий день |
| `src/04-ui.js` | кирпичики разметки: канбан, история, полоса стадий, свои списки |
| `src/05…08` | экраны |
| `src/09-shell.js` | меню, шапка, маршруты, действия, перетаскивание |
| `build.mjs` | склеивает всё в один файл |
| `check.mjs` | браузерный прогон: ошибки JS, пустые экраны, доска, дубли, роли, язык |

Модули нумерованы, потому что порядок в собранном файле имеет значение:
справочники и состояние объявляются раньше экранов, которые их читают.

## Ограничения

Прототип держит изменения в памяти вкладки: перенос карточки, отметка
рабочего дня, правка стадии и прав живут до перезагрузки. Шорт-лист вузов
сохраняется в `localStorage`. Это витрина, а не вторая реализация продукта:
всё, что требует настоящего сохранения, живёт в приложении.
