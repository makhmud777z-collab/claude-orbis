# Каталог вузов и подбор

## Состояние

Каталог — это база знаний продукта. Сейчас в нём 12 записей с **демо-данными**:
названия и цифры синтетические, каждая карточка помечена `dataStatus: "draft"`,
в интерфейсе висит предупреждение. Так сделано намеренно: сначала структура,
фильтры и алгоритм — потом наполнение. Ложные цифры под настоящими названиями
вузов хуже, чем честный черновик.

## Что хранит карточка

- Идентификация: название (латиница/корейский), город, регион, форма
  собственности, год основания, национальный рейтинг.
- Визовый статус вуза — от него зависит сложность получения D-2/D-4.
- Требования: TOPIK, IELTS, GPA, остаток на счёте, срок после выпуска.
- Деньги: стоимость года по каждой программе, общежитие, вступительный взнос,
  максимальный грант.
- Наборы (`2027 Весна`, `2027 Осень`) и список программ с направлением,
  уровнем, языком обучения и языковым порогом.
- Служебное: `dataStatus`, `sourceUrl`, `updatedAt`.

## Фильтры

Город · форма собственности · направление · уровень обучения · TOPIK студента ·
IELTS · бюджет на год · набор · общежитие · грант от 50% · языковой центр ·
визовый рейтинг.

Фильтр по бюджету считает **полную стоимость года** — обучение + общежитие (если
нужно) + вступительный взнос, — а не только цену обучения. Допуск 15% сверху:
вариант чуть дороже бюджета всё равно показывается, но помечается.

## Подбор под студента

Выбор студента в каталоге переносит его портфолио в фильтры одним действием и
включает оценку совпадения. Алгоритм — `src/lib/matching.ts`, чистая функция
без «магии»: оператор должен понимать, почему вуз оказался в шорт-листе.

| Критерий | Вес |
|---|---|
| Уровень обучения не совпал | блокирует |
| TOPIK ниже на 1 уровень / на 2+ | −22 / −45 и блокировка |
| IELTS: нет сертификата / ниже порога | −20 / −25 и блокировка |
| GPA ниже на ≤0.2 / больше | −10 / −25 и блокировка |
| Стоимость года выше бюджета до 15% / больше | −15 / −35 и блокировка |
| Город не из предпочтений | −12 |
| Другое направление | −18 |
| Другая форма собственности | −8 |
| Нет нужного набора | −14 |
| Нужен грант, а максимум < 50% | −10 |
| Нужно общежитие, а его нет | −12 |
| Ограничения по студенческой визе | −20 и блокировка |

Итог: балл 0–100 и вердикт — **сильное совпадение** (≥85), **подходит** (≥65),
**с риском**, **не проходит**. Каждый пункт возвращается текстом
(«TOPIK 4 ≥ 3», «дороже бюджета на $1 200»), и в интерфейсе видно все причины.

Работает и в обратную сторону: на карточке вуза есть блок «Кому из базы
подходит» — тот же алгоритм, прогнанный по студентам агентства.

## Этап 2: наполнение

Целевой конвейер (структура под него уже готова):

1. **Источники.** Для каждого вуза — официальная страница приёма иностранных
   студентов и PDF `admission guideline` соответствующего набора.
2. **Извлечение.** Разбор страницы и PDF в черновик карточки: требования,
   стоимость, дедлайны, программы.
3. **Проверка человеком.** Оператор сверяет черновик с источником. Карточка
   получает `dataStatus: "verified"`, `sourceUrl` и дату сверки.
4. **Отслеживание.** Новый набор — новый guideline; система сравнивает и
   поднимает задачу «данные вуза устарели».

Ключевое правило: цифры в каталоге всегда имеют источник и дату. Карточка без
источника остаётся черновиком и видна как черновик.
