# Роли и доступы

Роль отвечает на два вопроса сразу: **что можно делать** (права на модуль) и
**чьи записи видно** (зона видимости). Определения — `src/lib/rbac.ts`.

## Зоны видимости

| Зона | Что видно |
|---|---|
| `tenant` | все данные агентства |
| `branch` | только свой филиал |
| `own` | только свои студенты, заявки и задачи |

## Роли

| Роль | Зона | Суть |
|---|---|---|
| **Владелец** | агентство | всё, включая тариф, домен и удаление данных |
| **Директор** | агентство | вся операционка и аналитика; настройки без биллинга |
| **Руководитель филиала** | филиал | то же, что директор, но в пределах своего города |
| **Менеджер по продажам** | свои | лиды, первичная консультация, договор, передача куратору; документы своих студентов — только просмотр |
| **Куратор (оператор)** | свои | ведёт заявку: подбор вуза, документы, подача, переписка |
| **Специалист по документам** | филиал | проверка, апостиль, переводы, сроки годности |
| **Финансы** | агентство | договоры и оплаты; профили студентов — только чтение |
| **Агент-партнёр** | свои | внешний партнёр: видит только приведённых им студентов |

## Как это выражено в интерфейсе

- Навигация строится из `visibleModules(role)` — лишних разделов у роли просто нет.
- Кнопки действий проверяются через `can(role, module, action)`.
- Данные приходят из `scoped*()` — фильтр по зоне видимости стоит до рендера,
  а не прячет строки на клиенте.
- Прямой переход по ссылке на чужую запись даёт 404, а на закрытый раздел —
  понятный экран «раздел недоступен».

Матрица прав целиком видна в самой системе: «Сотрудники → Матрица прав».

## Что добавится

- Пользовательские роли (агентство собирает свою из набора прав).
- Передача студента между менеджерами с сохранением истории.
- Аудит: кто открывал и менял карточку (модель события `ActivityEvent` уже есть).
