# Дорожная карта

## Этап 1 — фасад и несущие конструкции (сделано)

- Доменная модель, роли и зоны видимости, мультиарендность по поддоменам.
- Все девять рабочих разделов на демо-данных.
- Алгоритм подбора вуза с объяснением каждого критерия.
- Дизайн-система и правила её применения.

## Этап 2 — данные и реальная работа

**Каталог вузов.** Конвейер из [UNIVERSITY-CATALOG.md](UNIVERSITY-CATALOG.md):
официальные страницы и admission guideline → черновик карточки → проверка
человеком → статус «проверено» с источником и датой.

**База.** Postgres, `tenantId` во всех таблицах, RLS. Репозитории вместо моков
за теми же интерфейсами.

**Аутентификация.** Вход по email/паролю и магической ссылке, привязка сессии к
арендатору по домену, приглашения сотрудников, 2FA для владельца и директора.

**Файлы.** Загрузка документов в S3-совместимое хранилище с версиями,
превью и правами доступа по роли.

**Мутации.** Перетаскивание карточек по этапам, редактирование профилей,
постановка задач — с записью в ленту событий (кто, что, когда).

## Этап 3 — то, ради чего систему оставляют

- Telegram-бот: заявка из бота сразу в воронку, статус для студента.
- Почта агентства: письма студентам и в вузы с домена агентства, переписка в
  карточке заявки.
- Напоминания: за 7/3/1 день до дедлайна — исполнителю и руководителю.
- Аналитика: конверсия по этапам, источникам, менеджерам и филиалам;
  средний срок прохождения этапа; причины отказов.
- Экспорт: шорт-лист вузов для семьи в PDF, реестр договоров в XLSX.
- Мобильный режим для менеджеров в поле.
