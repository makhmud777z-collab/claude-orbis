# Доменная модель

Все сущности живут внутри арендатора: у каждой записи есть `tenantId`.
Определения — `src/lib/types.ts`.

## Связи

```
Tenant ──┬── Branch
         ├── User ──────────┐
         ├── Student ───────┼── Application ── University ── Program
         │      │           │        │
         │      └── StudentDocument  └── Deadline (вычисляется)
         ├── Task ──────────┘
         └── ActivityEvent
```

## Tenant

Агентство. Ключевое поле — `slug`: он же поддомен. Плюс собственный домен,
тариф, число мест, филиалы, язык интерфейса по умолчанию, курс доллара
(`usdRate`) для пересчёта стоимости обучения и `edition` — версия продукта,
от которой зависит набор доступных модулей.

## User

Сотрудник агентства. Роль (`Role`) задаёт и права, и зону видимости —
см. [ROLES.md](ROLES.md). Привязан к филиалу.

## Student

Профиль студента. Отдельно вынесен `StudentProfile` — то, по чему идёт подбор:

| Поле | Зачем |
|---|---|
| `topik` (0–6), `topikExpiresAt` | главный фильтр по корейским программам, сертификат имеет срок |
| `ielts`, `gpa` | англоязычные треки и требования вузов |
| `budgetPerYear` | решающий фактор почти в каждой семье; в долларах, как публикуют вузы |
| `preferredCities` | Сеул / Пусан / регионы — влияет и на стоимость жизни |
| `preferredMajors` | медицина, инженерия, IT, дизайн… |
| `preferredOwnership` | национальный / государственный / частный |
| `degreeLevel`, `intake` | языковые курсы, бакалавриат, магистратура; набор |
| `needsDorm`, `needsScholarship` | влияют на полную стоимость года |

## Application

Заявка = связка «студент × программа вуза × набор». Живёт по этапам:

`new → consultation → matching → documents → submitted → university_review →
offer → visa → departed` (и `lost` в любой момент).

Хранит куратора, приоритет, ближайший внешний дедлайн, сумму договора и оплату
(**в сумах** — см. [MONEY-AND-LANGUAGE.md](MONEY-AND-LANGUAGE.md)).
У одного студента может быть несколько заявок — параллельные подачи это норма.

## StudentDocument

Пункт чек-листа досье: тип, файл, версия, статус
(`missing → requested → uploaded → verified | rejected | expiring`),
срок годности и признак «нужен апостиль». Базовый чек-лист — `DOCUMENT_CHECKLIST`
в `labels.ts`; часть пунктов появляется по профилю (нет TOPIK — нет и строки).

## Task

Задача от руководителя сотруднику: исполнитель, автор, срок, приоритет, статус
и привязка к студенту или заявке.

## Deadline

Не хранится, а **вычисляется** (`scopedDeadlines`) из трёх источников:
дедлайны заявок, сроки годности документов, сроки задач. Один источник правды:
поменялась заявка — сам собой поменялся календарь.

## University / Program

Вуз: город, регион, форма собственности, рейтинг, визовый статус, общежитие,
взнос, максимальный грант, требования (TOPIK/IELTS/GPA/счёт в банке/срок после
выпуска), наборы и список программ. Программа: направление, уровень, язык,
стоимость года, требования по языку.

Поле `dataStatus` (`draft` | `verified`) и `sourceUrl` — служебные: они
показывают, сверена ли карточка с официальным источником. Сейчас все записи —
черновики с демо-цифрами, и интерфейс об этом честно предупреждает.
